# Taskboard 会话生命周期与自动化下拉框设计

## 目标

解决两个相互影响的桌面端问题：

1. Taskboard 启动的 Codex（ChatGPT）退出后，启动器、注入器或本地服务残留，导致再次打开时被单实例锁拦截或连接到失效会话。
2. 自动化菜单中的原生 macOS 下拉框在 Codex 注入页面中无法稳定选择。

## 会话生命周期

`Codex Taskboard.app`、它启动的注入器、本地服务以及使用专用 profile 启动的 Codex 窗口共同组成一个会话。

- 启动时继续使用单实例锁。
- 启动新会话前读取已记录的子进程信息。只有进程命令与打包应用内的 Node 和注入器路径完全匹配时，才将其视为 Taskboard 残留进程并终止；不按名称批量结束其他 Codex 进程。
- 注入器需要区分“仍在等待首个 Codex 窗口”和“已成功连接后 Codex 窗口退出”。后者发生时，注入器正常退出。
- 注入器退出后，启动器终止其整个受管进程组、清除 PID/runtime 记录，然后退出自身，不再自动拉起新的 Codex。
- 用户再次打开 App 时，由全新的启动器、私有监听端口、认证令牌和调试管道建立新会话。
- 非 Codex 主窗口退出造成的瞬时 renderer 变化不应结束会话；只有专用 Codex 浏览器主进程或调试连接确定关闭才触发退出。

## 自动化下拉框

将“间隔”“模型”“推理强度”的原生 `<select>` 替换为同一套轻量自绘选择器。

- 点击字段按钮，在自动化设置面板内显示选项列表，不调用 macOS 原生选择菜单。
- 点击选项后立即沿用当前 `submitChange` 流程保存，并关闭当前选项列表，但保留自动化设置面板。
- 点击选择器外部、再次点击字段按钮或按 Escape 时，仅关闭选项列表；当没有选项列表打开时，Escape 才关闭整个自动化面板。
- 支持键盘焦点、方向键选择、Enter/Space 确认，并提供 `listbox`/`option` 语义。
- 切换模型后继续通过 `withAutomationModel` 规范化推理强度。
- 选项列表保持在自动化面板边界内，避免 portal 和原生弹层导致的外部点击误判。

## 错误处理与安全边界

- 残留 PID 已被复用或命令不匹配时只删除失效记录，不终止该进程。
- 正常退出使用 SIGTERM 并保留当前超时后的 SIGKILL 兜底。
- 清理过程即使部分文件已不存在也应保持幂等。
- 不接管普通方式启动的 Codex/ChatGPT，也不复用旧会话的私有认证信息。

## 测试与验收

- 源码/单元测试验证：已连接的 Codex 会话关闭后注入器退出；启动器不再自动恢复该会话；退出路径清理受管子进程和记录。
- 回归测试验证：失效 PID 或命令不匹配时不会误杀无关进程。
- 组件测试验证：三个自绘选择器均不再渲染原生 `<select>`，选择模型会提交并保留父面板。
- 运行完整测试、TypeScript 检查、Web 构建和 universal macOS App 构建。
- 安装替换前停止旧 Taskboard 会话，替换后启动 App；人工验证退出专用 Codex 后后台服务消失，再次打开可正常进入，同时模型下拉框可选择。

## 非目标

- 不让新启动器附着到旧的私有调试管道。
- 不改变普通 Codex App 的生命周期。
- 不增加常驻菜单栏程序或开机启动项。
