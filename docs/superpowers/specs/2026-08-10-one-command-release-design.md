# Codex Taskboard 一键发布与数据保留设计

## 目标

将当前应用发布为 `Codex Taskboard 0.2.2`，并提供一个专用的一键发布命令。后续发布默认自动递增补丁版本、同步所有版本来源、生成更新说明、构建 macOS 安装包，同时保证历史 Taskboard 数据不因应用替换或数据库升级而丢失。

## 实际操作路径

发布者从 `package.json` 中的一键发布脚本进入发布流程。发布脚本读取当前版本与 Git 改动，确定目标版本并同步 npm、Cargo 与 Tauri 配置；随后生成版本说明，调用现有 `app:build` 产出 `.app` 和 `.dmg`。安装阶段仅替换 `/Applications/Codex Taskboard.app`，数据继续从 `~/Library/Application Support/Codex Taskboard/` 读取。用户重新打开应用后，历史项目、议题、评论与自动化策略仍可见，安装包文件名和更新说明展示新版本号。

## 发布命令

新增专用发布命令，不改变普通开发构建的语义：

- 本次可显式指定 `0.2.2`。
- 后续不指定版本时，读取当前版本并自动递增补丁号。
- 同步 `package.json`、`package-lock.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`（若需要）和 `src-tauri/tauri.conf.json`。
- 生成或更新 `CHANGELOG.md`，并在 `dist/` 输出与安装包同版本的独立更新说明文件。
- 调用现有 universal macOS 构建流程，保留当前签名与验证步骤。
- 最终产物采用 `Codex Taskboard <version>.dmg` 的稳定名称。

普通 `npm run app:build` 不自动增加版本，避免测试构建无意污染版本历史。

## 更新说明生成

更新说明以当前工作区相对上一个发布版本的实际改动为依据，并允许发布命令接受人工补充说明。本次 `0.2.2` 至少记录：

- 适配 Codex 151 渲染与嵌入行为。
- 修复 Taskboard 启动、退出和残留后台服务生命周期。
- 修复自动化模型等下拉选项无法稳定选择的问题。
- 自动认领间隔迁移为 30 或 60 分钟，默认 60 分钟，降低重叠运行。
- 空的自动认领运行自动归档。
- 成功认领后按《认领时间 议题名称 自动认领》命名聊天。

## 历史数据保护

应用包与用户数据保持严格分离：

- 应用安装目录为 `/Applications/Codex Taskboard.app`。
- 历史数据目录为 `~/Library/Application Support/Codex Taskboard/`。
- 发布和安装流程不得删除、移动或覆盖整个数据目录。
- 替换应用前，将 Taskboard SQLite 数据库及自动化策略复制到带时间戳的备份目录。
- 安装前后读取数据库的项目数和议题数；若新应用无法读取数据库或计数异常减少，则停止完成安装并保留旧应用与备份。
- 数据库结构升级只能使用向前兼容迁移，不允许通过删除数据库重新初始化。

备份是发布安装的安全措施，不改变应用正常运行时的数据位置。

## 错误处理

- 版本格式非法或目标版本不高于当前版本时，发布命令在修改文件前失败。
- 任一版本文件同步失败时停止构建并报告具体文件。
- 构建失败时保留已生成日志与版本说明，不替换已安装应用。
- 数据备份或安装后验证失败时，不删除旧应用，也不清理备份。
- 缺少正式发布签名密钥时，本地包可完成本地签名与验证，但必须明确标记为本地安装包。

## 验证标准

- 所有版本来源均为 `0.2.2`。
- 产出 `Codex Taskboard 0.2.2.dmg` 和对应更新说明。
- `.app` 和 DMG 内应用能够通过本地代码签名验证并启动。
- 安装前后的项目数、议题数一致，`分析ppt-master` 仍处于待确认状态。
- 自动化仍为 60 分钟，并包含空运行归档与认领聊天命名规则。
- 再次执行一键发布且未指定版本时，目标版本计算为 `0.2.3`，但只有发布者确认执行后才写入版本文件。

## 范围外

- 不自动创建 Git 标签或推送远端。
- 不自动发布 GitHub Release。
- 不删除历史 DMG、历史数据备份或旧版本应用备份。
