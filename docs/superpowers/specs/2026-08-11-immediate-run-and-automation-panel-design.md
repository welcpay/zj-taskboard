# Codex Taskboard 立即执行与自动化面板设计

日期：2026-08-11

## 目标

为未开始执行的任务提供明确的“立即执行”入口，并重新整理自动认领设置面板的视觉层级。用户应能区分两种行为：手动立即执行单个任务，或开启自动化后周期性认领“等待认领”任务。

## 立即执行

“立即执行”按钮显示在主看板卡片底部，适用于以下任务：

- 状态为 `todo`（等待认领）；
- 状态为 `in_progress`（处理中），但没有任何已绑定的 Codex 对话。

点击后：

1. 锁定当前任务的执行按钮，防止重复点击。
2. 若任务仍为 `todo`，使用最新版本将其移动到 `in_progress`。
3. 创建新的 Codex 任务，写入该议题的处理指令并自动发送。
4. Codex 开始执行后，由现有 Taskboard 协议记录对话、评论和后续状态。

已有 Codex 对话或已有运行中处理记录的任务不显示“立即执行”，避免重复启动。创建或发送失败时，界面解除锁定并显示错误；如果本次操作曾把任务从 `todo` 移到 `in_progress`，则尝试恢复到 `todo`。恢复发生版本冲突时刷新看板，不覆盖其他客户端的新状态。

## 卡片布局

采用已确认的方案 B：卡片正文下方增加边界清晰的操作区。“查看详情”为次要按钮，“立即执行”为深色主按钮并带播放图标。操作区只在任务满足立即执行条件时出现，不让所有卡片持续增加视觉重量。

按钮保持固定高度和稳定宽度，执行中显示加载状态并禁用。点击按钮不得触发卡片打开、拖拽或属性菜单。

## 自动化设置面板

面板宽度约 360px，按以下顺序组织：

1. 标题、简短说明、自动认领总开关和当前状态。
2. 检查间隔分段按钮：`5`、`10`、`15`、`30`、`60`、`其他`。
3. 选择“其他”后显示 `0–60` 分钟数字输入；`0` 表示暂停。
4. 模型与推理强度并排排列，窄屏时改为单列。
5. “根据额度启用/关闭”作为次级设置，额度结果显示为独立状态提示。

面板沿用 Taskboard 的中性灰、白色表面和绿色运行状态，不引入新的主色。设置项使用 6–8px 圆角、清晰分隔和紧凑字号。下拉列表位于面板层级之上，鼠标从触发器移到选项时不会关闭；只有选择、点击面板外或按 Esc 才关闭。

## 状态与错误

- 自动化关闭：显示“已暂停”，等待认领任务不会自动执行。
- 自动化开启但没有 `todo`：本地检查继续运行，但不创建 Codex 聊天。
- 自动化开启且有 `todo`：只允许一个认领流程启动，任务离开 `todo` 后暂停对应 Codex 定时自动化。
- 立即执行与自动认领同时竞争同一任务：依赖任务版本检查，只有一个状态更新成功；失败方刷新并停止创建对话。
- 服务不可用：按钮和设置控件禁用，显示可重试的本地服务错误。

## 验证

自动化测试覆盖：

- `todo` 且无对话时显示并可触发立即执行；
- 未绑定对话的 `in_progress` 仍可立即执行；
- 已绑定或运行中的任务不显示按钮；
- 点击立即执行只提交一次；
- 状态更新冲突不创建 Codex 对话；
- 创建失败时恢复状态或刷新冲突状态；
- 自动化间隔分段选项、自定义输入、模型和推理强度仍提交现有设置协议；
- 下拉列表不会因鼠标移出触发器而关闭。
