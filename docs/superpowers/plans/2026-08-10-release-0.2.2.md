# Codex Taskboard 0.2.2 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Codex Taskboard 0.2.2 with safe one-command releases, preserved historical data, flexible 0–60 minute automation settings, and mutually exclusive claim runs.

**Architecture:** Keep ordinary development builds unchanged and add a release orchestrator that owns version synchronization, release notes, data backup, build, local signing, artifact naming, and verification. Extend the existing Taskboard automation contract to accept integer intervals from 1 through 60 while treating 0 as a pause request; use an atomic per-project lock instruction in the automation prompt so overlapping claim runs exit and archive before touching issues.

**Tech Stack:** Node.js 22 ESM scripts, React 19/TypeScript, Tauri 2/Rust, Node test runner, macOS `codesign`, SQLite data under Application Support.

---

## File Structure

- Create `scripts/release-app.mjs`: one-command release orchestration and explicit `--version`/automatic patch selection.
- Create `scripts/release-notes.mjs`: deterministic Markdown release-note rendering from supplied entries and current version.
- Create `scripts/install-local-release.mjs`: data snapshot, installed-app replacement, reopen, and post-install count verification.
- Create `test/release-app.test.mjs`: version parsing, synchronization targets, artifact names, and dry-run behavior.
- Create `test/install-local-release.test.mjs`: data directory preservation and count-comparison behavior using temporary fixtures.
- Modify `package.json`, `package-lock.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`: set 0.2.2 and expose release scripts.
- Modify `CHANGELOG.md`: add the 0.2.2 release entry.
- Modify `shared/taskboard-automation.mjs`: accept 1–60, encode overlap locking, and map zero to pause without emitting an invalid RRULE.
- Modify `web/src/App.tsx`: store and parse 0–60 minute settings.
- Modify `web/src/components/ProjectAutomationMenu.tsx`: add presets, “其他”, bounded numeric input, and zero-as-pause behavior.
- Modify `web/src/styles.css`: style the compact custom interval editor and validation message.
- Modify `scripts/codex-injector.mjs`: restore all valid 0–60 policies without forcing legacy values to 60.
- Modify `test/taskboard-automation.test.mjs` and `test/project-automation-settings.test.mjs`: cover the direct automation path.

- [ ] **Step 3: Implement one interval validator**

In `shared/taskboard-automation.mjs`, replace the set with:

```js
function validIntervalMinutes(value, { allowPause = true } = {}) {
  return Number.isInteger(value)
    && value >= (allowPause ? 0 : 1)
    && value <= 60;
}
```

Use `allowPause: true` for host policies and `allowPause: false` for RRULE/spec generation. Update RRULE validation to parse the number and accept 1–60.

- [ ] **Step 4: Make zero pause the existing automation**

In the policy application path, calculate:

```js
const shouldRun = request.enabledByUser
  && request.intervalMinutes > 0
  && (!request.quotaAware || quota?.state === "available");
```

This keeps the stored user setting while sending `pause` instead of creating `INTERVAL=0`.

- [ ] **Step 5: Preserve valid stored intervals**

Change `restoredAutomationPolicy` to preserve integer values from 0 through 60 and default invalid legacy data to 60.

- [ ] **Step 6: Update web parsing**
